Kali Linux™ Graphical Desktop on Windows 11 with WSL2

Run Kali Linux on Windows 11 under WSL2. You can open single Linux GUI apps through WSLg, or run the full Kali desktop in a window through Win-KeX.

Most recent guide.

1. Install WSL2 2. Install Kali 3. Update packages 4. Single GUI apps 5. Full desktop 6. Shut down 7. Troubleshooting

1 Install WSL2

  1. Right-click Start and pick Terminal (Admin).
  2. If WSL is not on this PC yet, run:
    wsl --install

This turns on the Windows features WSL needs and, on a first install, also sets up Ubuntu by default. Restart when Windows asks you to. To install Kali in that first step instead, use wsl --install -d kali-linux.

If wsl --install only prints help text, WSL is already installed. Skip ahead to installing Kali.

Then update WSL and make sure version 2 is the default:

wsl --update
wsl --set-default-version 2

After a WSL update, shut the subsystem down once so the new version is used:

wsl --shutdown

2 Install Kali

Open a normal Terminal or PowerShell window and run:

wsl --install -d kali-linux

When the Kali window opens, create a UNIX username and password. This account gets sudo rights inside Kali. You will not see characters as you type the password.

Confirm Kali is running as WSL 2:

wsl --list --verbose

If an existing Kali install still shows version 1, upgrade it:

wsl --set-version kali-linux 2

3 Update packages

Inside Kali:

sudo apt update && sudo apt upgrade -y

4 Option A: Single GUI apps (WSLg)

Windows 11 includes WSLg, so individual Linux GUI apps can open in their own Windows windows. This is not a full Kali desktop. Microsoft also recommends installing the GPU driver for your machine (Intel, AMD, or NVIDIA) so Linux apps can use hardware-accelerated OpenGL. Those driver links are on the WSLg page in Sources checked.

If WSL was already on the PC before you started, update it and restart WSL first:

wsl --update
wsl --shutdown

Then, inside Kali:

sudo apt install x11-apps firefox-esr -y
firefox-esr &

Each Linux app opens in its own window. Installed GUI apps also show up in the Windows Start menu under the distribution name.

5 Option B: Full Kali desktop (Win-KeX)

Win-KeX is the official Kali method for a full graphical desktop under WSL 2. Install it inside Kali. The kali-win-kex package recommends kali-desktop-xfce, and apt installs recommended packages by default, so you get the Xfce desktop with it:

sudo apt update
sudo apt install -y kali-win-kex

If the Xfce desktop is missing, install it yourself:

sudo apt install -y kali-desktop-xfce

Start Window mode with sound. This opens the full Kali desktop in a dedicated window, which is the usual way to get a GUI desktop on WSL 2:

kex --win -s

You can also start it from PowerShell or Command Prompt:

wsl -d kali-linux kex --win -s

The first time you start Window mode, Win-KeX asks you to set a VNC server password. You can change it later with kex --passwd. The -s flag (same as --sound) turns on sound. The first time you use sound, choose Public networks if Windows Defender Firewall asks for permission.

The desktop starts in full screen. Press F8 to open the Win-KeX menu, where you can leave full screen or choose Exit viewer. Exit viewer closes the viewer but leaves the session running. Reconnect with:

kex --win --start-client

Win-KeX also has two other official modes:

  • Seamless mode places a Kali panel on your Windows desktop so Kali and Windows apps share the same screen:
    kex --sl -s
  • Enhanced session mode uses Windows Remote Desktop. This is the supported mode on ARM devices. The --ip flag is Kali's documented ARM workaround:
    kex --esm --ip -s

Kali lists Windows Terminal as a Win-KeX prerequisite. You can still start any of these modes from the Kali shell or from a Windows command prompt as shown above.

6 Shut down cleanly

To close the viewer only, press F8 and choose Exit viewer. To stop the Window mode server, run this inside Kali:

kex --win --stop

If you started a different mode, stop that mode instead: kex --sl --stop or kex --esm --stop.

Stop all of WSL from PowerShell or Command Prompt:

wsl --shutdown

7 Troubleshooting

Check that WSL is present and up to date:

wsl --status
wsl --version
wsl --update

Win-KeX and WSLg both need WSL 2. Confirm Kali's version with wsl --list --verbose. If it still says 1, run wsl --set-version kali-linux 2.

If the desktop window is black, or Win-KeX fails after a WSL update, stop the session, update WSL, and restart it:

kex --win --stop
wsl --update
wsl --shutdown

Open Kali again, then start Window mode with kex --win -s.

A WSL update can leave a WSLg socket that blocks Win-KeX. Official Win-KeX commands can check, remove, and later restore that socket:

kex --wslg-status
kex --wslg-remove
kex --win -s

When you want WSLg single-app windows again, run kex --wslg-restore.

If Window mode still reports that /tmp/.X11-unix is read-only (a known issue after some WSL Store updates), remount it and try again:

sudo mount -o remount,rw /tmp/.X11-unix
kex --win -s
