Kali Linux™ Desktop on Windows 10 with WSL2 and Win-KeX

Set up a full Kali desktop on a clean Windows 10 install, using WSL2 and Win-KeX.

Requirement: wsl --install needs Windows 10 version 2004 (build 19041) or later.[1] WSL 2 itself can run on older x64 builds: version 1903, build 18362.1049 or later. ARM64 needs version 2004, build 19041 or later.[2] Check your build with Win+R, then winver.

Most recent guide. Windows 10 reached end of support on 14 October 2025.

1. Turn on WSL2 2. Older builds 3. Default to WSL2 4. Install Kali 5. Install Win-KeX 6. Start the desktop 7. Shut down 8. Troubleshooting

1 Turn on WSL2

If your PC is on version 2004 (build 19041) or later[1], right-click Start, open PowerShell (Admin), and run:

wsl --install

This turns on the Windows features WSL needs and, on a first install, also sets up Ubuntu by default.[1] Restart when it finishes. To install Kali in that first step instead, use wsl --install -d kali-linux.

If wsl --install only prints help text, WSL is already installed. Skip ahead to making WSL 2 the default, then install Kali.

2 Older Windows 10 builds (no wsl --install)

If your build is older than 19041, or wsl is not recognized, use the manual WSL 2 steps.[2] In PowerShell or Command Prompt as Administrator:

dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all

Restart when prompted. Then install the WSL 2 Linux kernel update from https://aka.ms/wsl2kernel and restart again.

3 Make WSL2 the default and update it

wsl --update
wsl --set-default-version 2

Recent versions of wsl --install already default to WSL 2. The set-default-version command confirms it. After a WSL update, shut the subsystem down once so the new version is used:

wsl --shutdown

4 Install Kali

wsl --install -d kali-linux

Wait for the install to finish, then create a UNIX username and password. You will not see characters as you type the password.

Confirm Kali is running as WSL 2:

wsl --list --verbose

If an existing Kali install still shows version 1, upgrade it:

wsl --set-version kali-linux 2

5 Update and install Win-KeX

Win-KeX is the official Kali method for a full graphical desktop under WSL 2.[6] Inside Kali, update packages and install it. The kali-win-kex package recommends kali-desktop-xfce[10], and apt installs recommended packages by default, so you get the Xfce desktop with it:

sudo apt update && sudo apt upgrade -y
sudo apt install -y kali-win-kex

If the Xfce desktop is missing, install it yourself:

sudo apt install -y kali-desktop-xfce

6 Start the desktop

Start Window mode with sound.[7] This opens the full Kali desktop in a dedicated window:

kex --win -s

You can also start it from PowerShell or Command Prompt:

wsl -d kali-linux kex --win -s

The first time you start Window mode, Win-KeX asks you to set a VNC server password. You can change it later with kex --passwd. The -s flag (same as --sound) turns on sound. The first time you use sound, choose Public networks if Windows Defender Firewall asks for permission.

The desktop starts in full screen. Press F8 to open the Win-KeX menu, where you can leave full screen or choose Exit viewer. Exit viewer closes the viewer but leaves the session running. Reconnect with:

kex --win --start-client

Win-KeX also has two other official modes:

  • Seamless mode places a Kali panel on your Windows desktop so Kali and Windows apps share the same screen[8]:
    kex --sl -s
  • Enhanced session mode uses Windows Remote Desktop. This is the supported mode on ARM devices. The --ip flag is Kali's documented ARM workaround[9]:
    kex --esm --ip -s

Kali lists Windows Terminal as a Win-KeX prerequisite. You can still start any of these modes from the Kali shell or from a Windows command prompt as shown above.

On Windows 10 build 19044 or later, you can also run single Linux GUI apps through WSLg[4], without a full desktop. That needs WSL 2. Update WSL with wsl --update, then wsl --shutdown, and Microsoft recommends installing your GPU driver first.[4] Details are on the WSLg page in Sources checked. WSLg is not a full Kali desktop; use Win-KeX for that.

7 Shut down cleanly

Don't force-close the window. To close the viewer only, press F8 and choose Exit viewer, or log out from the desktop menu. To stop the Window mode server, run:

kex --win --stop

If you started a different mode, stop that mode instead: kex --sl --stop or kex --esm --stop.

Stop all of WSL from PowerShell or Command Prompt:

wsl --shutdown

8 Troubleshooting

Check your Windows build with Win+R, then winver. Check that WSL is present and up to date:

wsl --status
wsl --version
wsl --update

Win-KeX and WSLg both need WSL 2. Confirm Kali's version with wsl --list --verbose. If it still says 1, run wsl --set-version kali-linux 2.

If the desktop window is black, or Win-KeX fails after a WSL update, stop the session, update WSL, and restart it:

kex --win --stop
wsl --update
wsl --shutdown

Open Kali again, then start Window mode with kex --win -s.

A WSL update can leave a WSLg socket that blocks Win-KeX. Official Win-KeX commands can check, remove, and later restore that socket[11]:

kex --wslg-status
kex --wslg-remove
kex --win -s

When you want WSLg single-app windows again, run kex --wslg-restore.

If Window mode still reports that /tmp/.X11-unix is read-only (a known issue after some WSL Store updates)[12], remount it and try again:

sudo mount -o remount,rw /tmp/.X11-unix
kex --win -s
